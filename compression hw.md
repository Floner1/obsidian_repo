JPEG discards imperceptible colour detail per pixel block, colour differences the eye can't pick up, to shrink the file. MP3 works the same idea for audio, it throws away frequencies the ear can't hear to cut the file size.

ZIP bundles one or more files or folders into a single compressed file. That makes it easy to send multiple files in one email, and since zipping changes the apparent file type, it gets around email providers blocking certain file types, like .exe, as harmful content. It's also useful for uploading and downloading to servers, especially ones that auto-unzip on receipt.

Lossless compression is where data is encoded in a different way to reduce the amount of data. No data gets permanently removed, and the original file can be reconstructed. Lossless compression algorithms are used when accuracy and detail are essential. Common examples of lossless compression algorithms are PNG (images) and ZIP files.

Run length encoding (RLE) is a type of lossless compression. It finds runs of repeated values and replaces each run with one instance of the value plus a count, so the data ends up stored as pattern-count pairs. It's well suited to images with a small colour palette and blocks of solid colour, cartoons, line art, logos, where the same value repeats a lot. It's badly suited to photographs, since continuous colour variation means there aren't many repeated runs, and RLE can end up making the file bigger instead of smaller. The count always needs enough bits to hold the biggest possible run.

Dictionary-based compression is also a form of lossless compression. It finds repeated patterns, usually words, and unlike RLE those patterns don't have to sit next to each other. Each unique word gets a short code, and the code gets stored instead of the full word. A dictionary, the code list, gets stored too, so decompression can swap the codes back for the words. How many bits a code needs depends on how many unique words there are, in the worked example 36 unique words need 6 bits, since 2^6 = 64 covers it but 2^5 = 32 doesn't. The savings show up most on long or frequently repeated words, an 8-letter word stored at 128 bits in Unicode (8 characters x 16 bits) can drop to a single 6-bit code. Nothing gets thrown away, so the original text comes back exactly.

Compression ratio is the ratio of the original size to the compressed size, written as whole numbers in colon or fraction form, eg 1:5. An 8GB original compressed down to 2GB is written as 2:8, which simplifies to 1:4.

Saving percentage is the percentage of space saved. A 25GB original compressed to 16.25GB leaves the compressed file at 65% of the original size, so the saving percentage is 35%.
