JPEG reduces file size by discarding subtle colour variations within each pixel block that the eye cannot detect. MP3 follows a similar principle for audio, discarding frequencies beyond the ear's hearing range to reduce the file's size.

ZIP combines multiple files or directories into a single compressed archive. This simplifies sending several files in one email, and because the zip file changes its apparent file type, it can bypass email systems that block certain extensions, such as .exe. ZIP also aids in uploading and downloading on servers, particularly those that automatically unzip upon receiving the file.

Lossless compression encodes data differently to reduce its size without permanently discarding any information, allowing the original file to be fully reconstructed. These algorithms are preferred when precision and detail are crucial. Typical examples include PNG for images and ZIP for general files.

Run‑length encoding (RLE) is a lossless technique that replaces sequences of identical values with a single value and a count, storing the data as value‑count pairs. RLE is ideal for images with limited colour palettes and large uniform areas—such as cartoons, line art, or logos—where many pixels share the same colour. It is poorly suited to photographs, where continuous colour variations result in few long runs; in such cases, RLE can actually increase file size. The count must use sufficient bits to represent the longest possible run.

Dictionary‑based compression is another lossless method that replaces repeated patterns—often words—with short codes. Unlike RLE, these patterns need not be contiguous. Each distinct word receives a unique code, which is stored in place of the full word, and the code list itself is included in the file so that decompression can restore the original text. The number of bits per code depends on the number of unique words; for instance, 36 unique words require 6 bits, because 2⁶ = 64 covers the range while 2⁵ = 32 does not. This technique yields the greatest savings on long or frequently repeated words—for example, an eight‑letter word that would normally occupy 128 bits in Unicode (8 characters × 16 bits) can be represented by a single 6‑bit code. No information is lost, allowing the text to be reconstructed exactly.

The compression ratio expresses the relationship between the original size and the compressed size, usually written as whole numbers separated by a colon or as a fraction—for example, 1:5. If an 8‑GB file is compressed to 2 GB, the ratio would be 2:8, which simplifies to 1:4.

The saving percentage indicates how much space is reduced. For instance, compressing a 25‑GB file to 16.25 GB leaves the compressed file at 65 % of its original size, resulting in a 35 % saving.
